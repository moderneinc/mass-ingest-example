# Publishing to S3

Set `PUBLISH_URL=s3://your-bucket` and the CLI publishes through the AWS SDK; the container needs no AWS CLI. `repos.csv` and `repos-lock.csv` live at the bucket root.

| Variable | |
|---|---|
| `S3_PROFILE` | AWS profile name; the default credential chain otherwise. |
| `S3_REGION` | Region, for a bucket outside the credentials' default region. |
| `S3_ENDPOINT` | Endpoint URL for S3-compatible stores such as MinIO. |

Every standard credential provider works: an IAM role on EC2, ECS or Batch, `AWS_ACCESS_KEY_ID` / `AWS_SECRET_ACCESS_KEY` (and `AWS_SESSION_TOKEN`) in the environment, or a mounted `~/.aws` with a profile or SSO session. The principal needs `s3:GetObject` and `s3:PutObject` on the bucket's objects and `s3:ListBucket` on the bucket: a run reads the two csvs as well as writing them.

```bash
# environment variables (or the output of `aws configure export-credentials --format env`)
docker run --rm -p 8080:8080 -v "$(pwd)/data:/var/moderne" \
  -e PUBLISH_URL=s3://your-bucket -e AWS_REGION=us-east-1 \
  -e AWS_ACCESS_KEY_ID -e AWS_SECRET_ACCESS_KEY -e AWS_SESSION_TOKEN \
  mass-ingest

# a profile from a mounted ~/.aws (SSO sessions included; `aws sso login` first)
docker run --rm -p 8080:8080 -v "$(pwd)/data:/var/moderne" \
  -v ~/.aws:/home/moderne/.aws:ro -e PUBLISH_URL=s3://your-bucket -e S3_PROFILE=your-profile \
  mass-ingest

# MinIO or another S3-compatible store
docker run --rm -p 8080:8080 -v "$(pwd)/data:/var/moderne" \
  -e PUBLISH_URL=s3://moderne-lsts -e S3_ENDPOINT=https://minio.example.com -e AWS_REGION=us-east-1 \
  -e AWS_ACCESS_KEY_ID=minio-access-key -e AWS_SECRET_ACCESS_KEY=minio-secret-key \
  mass-ingest
```

## EC2 instance roles: raise the IMDSv2 hop limit

With an IAM role on the instance and no explicit credentials, the SDK asks the instance metadata service. Docker bridge networking adds a network hop, and IMDSv2's default hop limit of 1 keeps the container from reaching it, so `mod publish` fails with `Unable to contact EC2 metadata service`. Raise the limit to 2:

```bash
aws ec2 modify-instance-metadata-options --instance-id <instance-id> --http-put-response-hop-limit 2
```

The [AWS Batch](../3-scalability/aws-batch/) Terraform sets this on its launch template.

## The platform reads the bucket's catalog

For blob storage the Moderne platform reads the repository catalog from `repos-lock.csv`, which `mod publish` rebuilds from `repos.csv` on every run. A repository disappears from the platform only when it disappears from `repos.csv`, so keep the full list there and let your repository fetcher overwrite it. The CLI refuses to run when the file is missing.
