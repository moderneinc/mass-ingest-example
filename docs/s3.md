# Publishing to S3

An S3 bucket needs one variable, its URL:

```bash
MOD_LSTS_ARTIFACTS_S3_URL=s3://your-bucket
```

The URL names the bucket and nothing more. The CLI rejects a key prefix, because `repos.csv` and `repos-lock.csv` always live at the bucket's root.

## Credentials

The CLI talks to S3 through the AWS SDK and finds credentials wherever the SDK looks for them. Whichever principal it ends up with needs `s3:GetObject` and `s3:PutObject` on the bucket's objects and `s3:ListBucket` on the bucket itself. Read access is on that list because a run reads both csv files before it writes them.

On EKS, the best credential is no key at all. Associate an IAM role with the `mass-ingest` service account through [Pod Identity](https://docs.aws.amazon.com/eks/latest/userguide/pod-identities.html) (or IRSA), and the pods pick it up without anything in a secret:

```bash
aws eks create-pod-identity-association --cluster-name <cluster> \
  --namespace mass-ingest --service-account mass-ingest --role-arn <role-arn>
```

On any other cluster, add `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY` and `AWS_REGION` to the `mass-ingest-store` secret next to the bucket URL. With `docker run`, pass the same variables with `-e`, or use the output of `aws configure export-credentials --format env`.

Running the container straight on an EC2 instance has one trap. The instance role comes from the metadata service, and Docker's bridge network puts the container one hop further away than IMDSv2 allows by default, so `mod publish` fails with `Unable to contact EC2 metadata service`. Raising the hop limit to 2 fixes it:

```bash
aws ec2 modify-instance-metadata-options --instance-id <instance-id> --http-put-response-hop-limit 2
```

## Other regions and S3-compatible stores

`MOD_LSTS_ARTIFACTS_S3_REGION` sets the region when the bucket isn't in the credentials' default region. `MOD_LSTS_ARTIFACTS_S3_ENDPOINTURL` points the CLI at an S3-compatible store such as MinIO, which usually also means static keys:

```bash
kubectl -n mass-ingest create secret generic mass-ingest-store \
  --from-literal=MOD_LSTS_ARTIFACTS_S3_URL=s3://moderne-lsts \
  --from-literal=MOD_LSTS_ARTIFACTS_S3_ENDPOINTURL=https://minio.example.com \
  --from-literal=AWS_REGION=us-east-1 \
  --from-literal=AWS_ACCESS_KEY_ID=... --from-literal=AWS_SECRET_ACCESS_KEY=...
```
